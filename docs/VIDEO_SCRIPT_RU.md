# Сценарий непрерывного видео на 15-18 минут

Записывай свой экран и собственный голос одним дублем. Проект можно подготовить
заранее. Не называй невыполненные действия выполненными. Сначала добейся
настоящей успешной сборки Jenkins, затем записывай демонстрацию.

## 0:00-0:45. Представление

Покажи `cat Sarsembayev_Eldar_info.txt`.
«Меня зовут Eldar Sarsembayev. Моя группа IT2-2301, Student ID 37006.
Это моя лабораторная работа по DevOps. Я покажу связь Linux, Git, GitHub,
Docker и Jenkins на персональном приложении».

## 0:45-3:30. Linux, файлы и поиск

Покажи `pwd`, `ls -la`, пять обязательных папок, персональный файл, app.conf.
Продемонстрируй cd, mkdir, touch, cp, mv, rm на backup/demo. Покажи cat/head/tail.
Затем find application.log, grep ERROR, grep WARNING, grep -c ERROR, tail -n 5.
«Этот журнал содержит 10 учебных сообщений. grep фильтрует строки, find ищет
файлы. Здесь две строки ERROR и две WARNING».

## 3:30-5:30. Права, Bash, процессы

Покажи chmod 600/644 и ls -l. Объясни r/w/x, три группы доступа и 755.
Запусти `./scripts/Sarsembayev_Eldar_system.sh`. Покажи реальную ОС, память,
диск и проверку существования файла. Выполни ps, ps aux и top; назови реальный
PID, USER, %CPU и %MEM. «ps даёт снимок, top обновляет процессы». Выйди клавишей q.

## 5:30-8:00. Git и GitHub

Покажи git status, git log --oneline, минимум пять содержательных коммитов,
git show --stat для одного. Покажи .gitignore и git check-ignore.
Открой git branch, git log --graph --oneline --all, ветку development
и merge-коммит. Объясни, какие реальные изменения были объединены.
Покажи origin через git remote -v и настоящий репозиторий GitHub в браузере,
файлы, историю и ветку main. Не показывай токен или пароль.

## 8:00-11:00. Docker

Покажи Dockerfile и назови роль FROM, WORKDIR, COPY, RUN, EXPOSE, CMD.
Покажи docker images, docker ps и docker ps -a; открой приложение в браузере.
Объясни внутренний 8080 и внешний 8081 либо 8082 текущего запуска.
Покажи окружение через docker exec и логи через docker logs.
Продемонстрируй stop/start/rm на контейнере ручного запуска до следующей сборки.
«Image - шаблон, container - его экземпляр. Stop сохраняет экземпляр,
rm удаляет контейнер, а образ остаётся».

## 11:00-12:30. Compose

Покажи docker-compose.yml, docker compose config, up -d, ps, logs, down.
Обычный контейнер на 8081 к этому моменту должен быть остановлен.
Открой приложение и поясни, что YAML описывает воспроизводимый запуск.

## 12:30-16:30. Jenkins

Покажи Dashboard и job `Sarsembayev_Eldar_DevOps`. В настройках покажи GitHub URL,
ветку main, Script Path Jenkinsfile. Покажи Jenkinsfile, пять стадий и environment.
Нажми Build Now. Пока сборка идёт, объясняй: Checkout получает код, Build проверяет
компиляцию, Test запускает 11 тестов, Docker Build создаёт image, Docker Run
запускает container и проверяет health. После завершения открой реальные stages
и Console Output, имя/группу/ID, Git SHA и `Finished: SUCCESS`.
Покажи image build-N, работающий container, его logs и приложение на 8082.

## 16:30-18:00. Связь технологий и итог

«Linux - рабочая среда. Git фиксирует изменения. GitHub даёт удалённый источник.
Jenkins получает commit, проверяет приложение и строит Docker image.
Docker запускает container. При ошибке стадии следующие стадии пропускаются,
нужно исправить причину и повторить сборку. В этой демонстрации я показал
фактический результат всех стадий». Последнюю фразу используй только при успехе.

Проверь перед сдачей: читаемый текст, слышимый голос, цельная запись без обрывов,
личные данные в начале, доступная ссылка на видео, соответствие кода GitHub
и SHA успешной сборки. Сдавай собственную запись, а не озвучку чужого проекта.
